## php8 目录：基于 DHI 镜像的 PHP-FPM + Nginx 一体化 Dockerfile

- 目标：基于 `dhi.io/php:8-debian-fpm`（Docker Hardened Images）构建含 redis、rdkafka 扩展及 nginx/vim/curl/procps 的镜像。
- 用户原失败原因：DHI fpm 运行时变体**无 shell、无 apt、无 pecl**，`RUN` 指令无法执行（exec /bin/sh 直接报错）。
- 解决方案（三阶段构建，最终镜像文件 Dockerfile / nginx/default.conf / docker-entrypoint.sh / .dockerignore）：
  1. `dhi.io/php:8-debian-dev`（builder）：pecl 编译 redis、rdkafka（需 librdkafka-dev + pkg-config）。
  2. `dhi.io/php:8-debian-fpm`（fpm-src）：提取 php-fpm 二进制 + php-fpm.conf + php-fpm.d（dev 变体不带 php-fpm；无 fpm-dev tag）。
  3. `dhi.io/php:8-debian-dev`（运行时）：apt 装 nginx/vim/curl/procps/tzdata/librdkafka1，拷入 php-fpm 与扩展。
- 关键坑（DHI 精简 Debian/trixie）：
  - 缺 `adm` 组和 `www-data` 用户 → nginx-common postinst `chown www-data:adm` 失败，dpkg 报错；需手写 /etc/passwd、/etc/group 补齐（无 groupadd）。
  - ini 扫描目录是 `/opt/php-8.5/etc/php/conf.d`（不是官方镜像的 /usr/local/etc/php/conf.d）。
  - PHP 装在 `/opt/php-8.5`，扩展目录 `/opt/php-8.5/lib/php/extensions/no-debug-non-zts-20250925`。
  - php-fpm worker 以 nonroot(65532) 运行；dev/fpm 两 tag 当前均为 PHP 8.5.12 NTS，ABI 一致。
  - apt 源为 deb822 格式 `/etc/apt/sources.list.d/debian.sources`，sed 换阿里云源。
- entrypoint：无参数时 php-fpm --daemonize + nginx 前台 daemon off；有参数时直接 exec（调试用）。
- 验证结果：HTTP 响应正常，redis/rdkafka 已加载，nginx/vim/curl/ps 齐全。
- 按用户要求打 tag 构建：`hub.pengbei.tech:18080/bigdata/nginx-php:8.5.12`（811MB，sha256 前缀 d1a31b17393f，与 dhi-test 同一镜像）。
- 用户需要可复用的内部基础镜像（其他系统要 apt 装包）。方案：新增 `Dockerfile.base` 构建内部公共基础镜像 `hub.pengbei.tech:18080/bigdata/php-base:8.5.12`（= 8-debian-dev + 阿里源 + adm/www-data 修复 + php-fpm 拷入）。
- 坑：dhi.io/php:8-debian-dev 自带 `ENTRYPOINT ["php"]`，基础镜像需 `ENTRYPOINT []` 重置，否则 CMD 参数被当作 php 输入文件（"Could not open input file"）。
- `Dockerfile` 已重构为基于内部 base（ARG BASE_IMAGE 可切回 DHI 原始镜像），重新构建并回归验证通过（新镜像 sha256 前缀 31c7595a）。
- 参数调优（php/ 目录注入配置文件）：`php/99-overrides.ini`（memory_limit=200M、post_max_size=200M、upload_max_filesize=280M）、`php/zz-fpm-overrides.conf`（pm=dynamic、pm.max_children=50、pm.process_idle_timeout=60s、request_terminate_timeout=90s、clear_env=no，文件名 zz- 前缀保证最后合并生效）、nginx.conf sed `worker_processes 1`。全部经 `php -i` / `php-fpm -tt` / `nginx -T` 验证生效。
- 安装 cron 并随 entrypoint 启动。重大坑：**DHI 删除了 libpam-runtime 的 common-* conffiles，PAM 初始化解析 /etc/pam.d/ 全目录时因 @include 缺失文件而 abort（"Critical error - immediate abort"，报错实际来自 libpam 而非 cron）**，cron 任务全部静默失败。修复：基础镜像补建 common-auth/account/password/session/session-noninteractive 五个文件（Debian 标准最小内容）。排查手段：容器内 `grep -rl "immediate abort" /usr/lib` 锁定 libpam，strace -f 跟踪 openat 发现 ENOENT。另发现 `date` 输出 UTC——ENV TZ 不传递给 cron 子进程，需 `ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime` + /etc/default/locale 写 TZ。
- PHP 日志链路：php.ini log_errors=On + error_log 空 → FPM 错误通道 → stderr → docker logs；正常请求只有 fpm access 一行；echo/var_dump 走 HTTP 响应体不进日志。
- 排查用户应用容器 hardcore_einstein（rmt_media:latest，基于 nginx-php 构建的应用镜像）：index.php 加 `echo 'asdf'` 无输出。根因：**应用镜像自带的 nginx 站点配置 `location ~ \.php$` 块缺少 `include fastcgi_params/fastcgi.conf` 和 `SCRIPT_FILENAME`**，php-fpm 收不到脚本路径，返回空 200（带 X-Powered-By 头，极具迷惑性）。诊断手法：放一个纯 echo 的 t2.php 仍 0 字节 → 排除框架/文件问题；CLI 直跑 `php index.php` 正常输出 → 锁定 nginx→FPM 传参。容器内现场在 fastcgi_pass 前加 `include fastcgi.conf;` 后 echo 立即生效。**用户需把此修复固化到应用镜像的 nginx 配置**。另注意：该 CodeIgniter 老框架在 PHP 8.5 下有 E_STRICT 移除等 Deprecated 报错（框架兼容性问题，非镜像问题）。
